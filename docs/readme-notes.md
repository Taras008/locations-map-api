# Нотатки для README

Робочий список того, що треба описати в README на фінальному етапі. Після перенесення — видалити файл.

## Auth: інтеграція фронтенду
- CSRF: спершу `GET /api/v1/auth/csrf/` (ставить cookie `csrftoken` і повертає токен у тілі),
  далі заголовок `X-CSRFToken` у кожному POST/PATCH/DELETE, включно з login/register/password reset.
- Після успішного login і register Django ротує CSRF-токен (захист від session fixation).
  Фронтенд має перечитати `csrftoken` (cookie або повторний `GET auth/csrf/`), інакше
  наступний небезпечний запит отримає 403 `csrf_failed`.

## Auth: свідомі компроміси
- Реєстрація розкриває, чи зареєстрований email (400 з помилкою по полю `email`) — без цього
  користувач не зрозуміє, чому не може створити акаунт. Пом'якшено throttle `register`
  (5/год на IP). Скидання пароля, навпаки, завжди відповідає 204, а login дає однакову
  помилку для неіснуючого email і неправильного пароля.
- Login обмежено двома лімітами: за IP (`login`, 10/хв) і за акаунтом (`login_email`, 5/хв,
  ключ — SHA-256 нормалізованого email). Зворотний бік — зловмисник може на хвилину
  заблокувати вхід у чужий акаунт; для такого масштабу прийнятно, у production можна
  доповнити CAPTCHA після N невдалих спроб.
- Скидання пароля завжди відповідає 204, навіть якщо брокер Celery недоступний: помилка
  постановки задачі лише логується (`common.queue.enqueue_on_commit`). Лишається слабкий
  часовий канал: для відомого email запит трохи довший через публікацію в Redis. Повністю
  його прибирає лише постановка задачі для будь-якого email (і перевірка вже у worker'і) —
  для цього проєкту не робимо.

## Рейтинг і популярність
- `avg_rating`, `reviews_count`, `views_7d`, `views_total`, `popularity` — анотації
  `selectors.annotate_stats()`, у БД не зберігаються. Перегляди рахуються окремими Subquery:
  JOIN переглядів поруч із відгуками множив би рядки й ламав Avg/Count.
- Формула (коефіцієнти — env `POPULARITY_*`):
  `bayes = (sum(ratings) + M·C) / (n + M)`, M=5, C=3.0;
  `popularity = 2.0·bayes + 1.5·ln(1+n) + 1.0·ln(1+views_7d)`.
  Байєсівське згладжування: один відгук «5» не обганяє 20 відгуків із середнім 4.7.
  Логарифми: кількість відгуків і переглядів дає спадний приріст і не задавлює якість.
- Свідомий наслідок: будь-яка активність підвищує популярність — локація з одним відгуком «1»
  стоїть вище за локацію без відгуків (≈6.37 проти 6.0). Популярність — це «помітність»,
  а не якість; для якості є сортування за `avg_rating`.
- Без відгуків `avg_rating = null`: у сортуванні за рейтингом такі локації завжди в кінці
  (в обидва боки), фільтри `min_rating`/`max_rating` їх не повертають.

## Фільтри списку
- `bbox=min_lng,min_lat,max_lng,max_lat` (видима область мапи); `min_lng > max_lng` означає
  перетин антимеридіана 180°.
- `category`/`author` — за id; невідомий id дає порожній список, а не 400 (без зайвого запиту).
- Сортування стабільне: тай-брейк за `-id`, тож сторінки не перекриваються.
